# P02 session bridge

[Decision 0010](decisions/0010-p02-session-bridge.md) governs this bounded implementation. The application remains unable to issue a login or grant account access. There are no providers, database adapter, development login, refresh tokens or runtime memory authority. Supplying `NEXTAUTH_SECRET` does not enable sign-in. Existing hosted credentials remain read-only and are not used for sessions.

## Boundaries

`GET /api/auth/session` accepts only the `__Host-shipsense.session-token` cookie (including contiguous chunks 0–7). Duplicates, mixed base/chunks, gaps, unexpected suffixes, oversized input, invalid encryption and expired canonical deadlines fail closed. Authorization headers never supply browser session authority. The encrypted envelope carries a private random handle and timing bounds; successful public sessions contain only `expires`. No provider tokens, account data, roles or handles are returned.

Before the NextAuth session handler runs, the BFF independently resolves the canonical handle. Creation and absolute expiry must match the envelope; idle expiry cannot exceed either canonical state or the envelope. NextAuth retains responsibility for encryption. Encoded expiry is checked after encryption; positive cookies use an absolute `Expires` without a rolling `Max-Age`. Chunk cleanup retains deletion attributes. Cookies are always HttpOnly, Secure, SameSite=Lax, Path=/, with no Domain. HTTPS is required for a future browser login; the local HTTP UI can demonstrate only the unavailable state.

FastAPI exposes service-authenticated `POST /internal/v1/auth/session/resolve` and `/revoke`. The production composition has an empty public-key registry and unavailable session port, so it grants no authority. The internal snapshot is not a user principal or permission grant. Every future protected operation must resolve canonical account/session/epoch and scoped authorization again in its unit of work. The durable adapter must atomically enforce revocation, account state, expiry and audit correlation; it must not advance the absolute deadline. Tests use explicit synthetic ports only.

The server transport fixes its current destination to the documented local API, uses a three-second deadline, refuses redirects, validates correlation and bounded response shape, and normalizes failures without upstream details. Its RS256 credential has fixed `iss=shipsense-web`, `aud=shipsense-auth`, `sub=shipsense-bff`, one exact `session:resolve` or `session:revoke` scope, integer `iat/nbf/exp`, a 60-second lifetime and random `jti`. The API rejects duplicate headers/claims, extra claims/header fields, wrong algorithms/keys/audience/scope/types, oversized tokens and more than 30 seconds of skew. Only explicitly active public keys in the fixed registry are usable; overlapping active keys permit rotation, retired keys deny immediately. Key validity bounds must contain the credential lifetime. Worker and browser credentials cannot substitute for these auth-only credentials. Deployment signing-key custody must use Azure secret management; no private key is stored or configured by this slice.

## Logout and degraded behavior

`POST /api/auth/signout` requires exact same-origin Origin and application/json. The trusted origin is `NEXTAUTH_URL` (an origin without a trailing path), defaulting to the documented local `http://127.0.0.1:3000`; it is never derived from forwarded host headers. Configure it to the actual browser origin, since Next.js's internal request URL can differ. It confirms canonical revoke before reporting `revoked`; cookie deletion happens even if canonical revoke fails. A missing/invalid/expired cookie, missing secret or unavailable authority yields `revocation_unconfirmed` with 503 and bounded cookie deletion. A browser page exposes this uncertainty through a live status region. A network failure or denied request offers retry without claiming cookie deletion. Local logout never claims global Google/GitHub logout or immediate detection of external provider disablement. GET signout and all login/callback/update actions remain unavailable.

## Verification and remaining gates

[Decision 0011](decisions/0011-p02-canonical-session-lifecycle.md) adds internal [strict session/account/audit records and lifecycle rules](../packages/domain/src/shipsense_domain/sessions.py), plus [canonical API composition](../services/api/src/shipsense_api/session_authority.py). Handles are looked up only by SHA-256 digest. Resolve checks account identity, active status, authentication epoch, revocation and both deadlines at server time, without extending idle time. Neither the handle nor its digest is exposed in a snapshot or audit event.

The transaction port fences session and account state through commit. Resolve releases its snapshot only after its redacted receipt commits; revoke commits the revision change and receipt together. An unknown or already revoked handle is an idempotent revoke success, with a separate receipt for each request and no second state transition. Unknown/revoked/expired resolve returns the same denial. Audit/read/commit failure returns unavailable without protected output or a success claim. Authentication receipts use an explicitly unscoped partition and the authenticated BFF actor; they contain no tenant claim, account identifier or denied-object detail. Correlation identifies an attempt, not a grant or idempotency key.

The [synthetic transaction tests](../services/api/tests/test_canonical_sessions.py) cover rollback, equal denial envelopes, fixed deadlines, epoch change, redaction and serialized resolve/revoke races. Their copy-on-commit storage exists only in tests. It does not prove MongoDB transactions, database concurrency, restart durability or provider revocation. There is no runtime store, environment switch, login issuer, database write/index or new route/scope in this slice. A future authorized adapter must satisfy the documented fence, compare-and-set, bounded retry and atomic commit contract before runtime composition can change.

Run `npm run quality`, `npm run test:unit`, `npm run build`, and `npm run test:smoke` from the primary checkout. [Web security tests](../apps/web/tests/session-bridge.test.ts) exercise the pinned NextAuth handler, bounded renewal, cookie extraction/chunks/deletion, credential transport and logout failure. [API security tests](../services/api/tests/test_session_bridge.py) exercise actual RSA signatures, a Node-signed credential verified in Python, rotation, strict negative cases, canonical outage/revoke, default denial and correlation. OpenAPI documents the service security requirement and is checked against generated TypeScript.

Real Google/GitHub/password/mail flows, provider proof and linking, authorized persistent writes/indexes/migrations, durable audit/session/epoch concurrency, worker/callback authority and measured external revocation guarantees remain required before completing P02.2. Email normalization is not selected or implemented here. No provisioning, provider write or spending is implied.
