# Local foundation setup

Use the supplied primary checkout. Required versions: Node 26.7.0, npm 11.19.0, Python 3.14.7 and uv 0.12.21. Runtime/version files and root locks define initial reproducibility. Do not substitute floating versions. Package registries are required for a fresh install; no cloud or provider credentials are required.

From the repository root:

```powershell
git config core.hooksPath .githooks
npm ci
uv sync --frozen --all-packages --all-groups
npm run contracts:generate
npm run contracts:check
npm run test:foundation
python scripts/validate-foundation.py
uv build --package shipsense-api
uv build --package shipsense-worker
uv run --frozen --package shipsense-worker shipsense-worker
npm run typecheck:web
npm run build:web
```

Run the API: `uv run --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000`. In another terminal run the web: `npm run start --workspace apps/web -- --hostname 127.0.0.1`. Visit `http://127.0.0.1:3000`, API `/foundation`, `/docs` and `/openapi.json` on port 8000. Stop each foreground process with Ctrl+C. The web diagnostics call the versioned API; dependency readiness remains safe 503 until the separate real-adapter wiring is accepted.

No environment file is needed. `SHIPSENSE_PROFILE` accepts only `local`; other profiles fail closed. Test a missing fixture with `python scripts/validate-foundation.py --fixture tests/fixtures/absent.json` (expected exit 2, `FIXTURE_MISSING`). Use `--config infra/absent.json` for `CONFIG_MISSING`. Errors contain codes rather than supplied file contents.

## Quality checks

Before the frozen Python install, run `uv lock --check` to reject a stale
manifest/lock pair (`--frozen` itself deliberately skips freshness validation).
The root `.npmrc` rejects unsupported Node/npm engines.

After both frozen installs above, run `npm run quality`. It checks formatting,
lint, strict TypeScript/Python types, offline secrets and canonical generation
drift in that order. Run each target independently when diagnosing a failure:

```powershell
npm run format:check
npm run lint
npm run typecheck
npm run secrets:check
npm run contracts:check
```

`npm run format` applies Prettier and Ruff. ESLint covers maintained JavaScript,
TypeScript and TSX; Ruff covers maintained Python services, tests and scripts.
mypy checks API/worker sources and scripts with strict settings. Generated
TypeScript is typechecked and compared with freshly generated bytes, rather
than formatted. Historical accepted decisions and phase plans retain their
source formatting. The staged Markdown hook continues to check all staged
Markdown for trailing whitespace and a final newline.

`contracts:check` regenerates OpenAPI and TypeScript into an operating-system
temporary directory, byte-compares both artifacts and fails without repairing
drift. After an intentional API change, use `contracts:generate`, inspect both
generated diffs, then run the quality gate.

The secret gate uses detect-secrets offline with no baseline, credential
verification or inline allowlist. It enumerates tracked and nonignored
untracked files, including `.env.example`, source and tests. Findings report
only path, line and rule; scanner errors fail with a generic redacted message.
Known PDF/icon assets are skipped by suffix and signature. Unsupported binary
source, unreadable inputs and files over 10 MB fail closed. Full npm SHA-512 integrity fields and verified public fixture payload/provenance hashes are the only entropy exceptions. Fixture payload hashes are recomputed from bounded local bytes; provenance must equal the schema pin. Other source/lockfile content is scanned. Keep actual local `.env` files ignored and never commit
credentials. Review every finding rather than generating a blanket baseline.

The minimal quality workflow uses read-only permissions, pinned action SHAs,
no provider secrets, a 15-minute deadline, frozen installs and `npm run quality`.
Required independent seeded CI failure/recovery proof remains an acceptance
gate until verified on the remote workflow. Jira owns development-key checks;
this workflow does not duplicate or prove Jira linkage. Update pins deliberately,
regenerate the relevant root lock, inspect audit/peer compatibility, and repeat
frozen installation plus affected behavior and failure/recovery checks. Do not
use peer bypasses or automatic audit fixes.

The workflow also runs `uv run --frozen python scripts/verify-quality-gates.py`.
This serial verification command places reversible synthetic probes in actual
checked paths, asserts each target and the aggregate fail for the intended
rule, removes the probe and asserts recovery. It restores original contract
bytes in `finally` and refuses to overwrite an existing source probe. Hold
exclusive checkout access while running it. Local execution does not establish
remote CI acceptance.

The [local service runbook](../infra/local/README.md) covers pinned Mongo/private S3, explicit idempotent seed, scoped stop/reset and same-process queue commands. Run `npm run test:local`; use its explicit external-state instructions for real integration tests. The existing web/version/liveness diagnostic slice is accepted; full API readiness wiring and P01.5 clean build/unit/smoke CI remain separate. Quality success alone does not establish those outcomes.
