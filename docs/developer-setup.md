# Local foundation setup

Use the supplied primary checkout. Required versions: Node 26.7.0, npm 11.19.0, Python 3.14.7 and uv 0.12.21. Runtime/version files and root locks define initial reproducibility. Do not substitute floating versions. Package registries are required for a fresh install; no cloud or provider credentials are required for installs, builds or diagnostics. Hosted readiness needs existing MongoDB and private Cloudflare R2 access.

From the repository root:

```powershell
git config core.hooksPath .githooks
npm ci
uv sync --frozen --all-packages --all-groups
npm run contracts:generate
npm run contracts:check
npm run test:foundation
python scripts/validate-foundation.py
uv build --package shipsense-api
uv build --package shipsense-worker
uv run --frozen --package shipsense-worker shipsense-worker
npm run typecheck:web
npm run build:web
```

Run the API: `uv run --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000`. In another terminal run the web: `npm run start --workspace apps/web -- --hostname 127.0.0.1`. Visit `http://127.0.0.1:3000`, API `/foundation`, `/docs` and `/openapi.json` on port 8000. Stop each foreground process with Ctrl+C. The web diagnostics call the versioned API; dependency readiness stays safely503 until valid hosted configuration and authorized dependency access are available.

For credential-free diagnostics no environment file is needed. For hosted dependencies, copy root `env.example` to ignored `.env`, fill its placeholders privately and launch the API with `uv run --env-file .env --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log`. See the [API configuration contract](../services/api/README.md). Do not load that credential file into the web process; it needs only server-side `SHIPSENSE_API_ORIGIN`. No MongoDB/S3 self-hosting, Docker startup or seed is required for application setup. `SHIPSENSE_PROFILE` accepts only `local`; other profiles fail closed. Test a missing fixture with `python scripts/validate-foundation.py --fixture tests/fixtures/absent.json` (expected exit 2, `FIXTURE_MISSING`). Use `--config infra/absent.json` for `CONFIG_MISSING`. Errors contain codes rather than supplied file contents.

## Quality checks

Before the frozen Python install, run `uv lock --check` to reject a stale
manifest/lock pair (`--frozen` itself deliberately skips freshness validation).
The root `.npmrc` rejects unsupported Node/npm engines.

After both frozen installs above, run `npm run quality`. It checks formatting,
lint, strict TypeScript/Python types, offline secrets and canonical generation
drift in that order. Run each target independently when diagnosing a failure:

```powershell
npm run format:check
npm run lint
npm run typecheck
npm run secrets:check
npm run contracts:check
```

`npm run format` applies Prettier and Ruff. ESLint covers maintained JavaScript,
TypeScript and TSX; Ruff covers maintained Python services, tests and scripts.
mypy checks API/worker sources and scripts with strict settings. Generated
TypeScript is typechecked and compared with freshly generated bytes, rather
than formatted. Historical accepted decisions and phase plans retain their
source formatting. The staged Markdown hook continues to check all staged
Markdown for trailing whitespace and a final newline.

`contracts:check` regenerates OpenAPI and TypeScript into an operating-system
temporary directory, byte-compares both artifacts and fails without repairing
drift. After an intentional API change, use `contracts:generate`, inspect both
generated diffs, then run the quality gate.

The secret gate uses detect-secrets offline with no baseline, credential
verification or inline allowlist. It enumerates tracked and nonignored
untracked files, including `env.example`, source and tests. Findings report
only path, line and rule; scanner errors fail with a generic redacted message.
Known PDF/icon assets are skipped by suffix and signature. Unsupported binary
source, unreadable inputs and files over 10 MB fail closed. Full npm SHA-512 integrity fields and verified public fixture payload/provenance hashes are the only entropy exceptions. Fixture payload hashes are recomputed from bounded local bytes; provenance must equal the schema pin. Other source/lockfile content is scanned. Keep actual local `.env` files ignored and never commit
credentials. Review every finding rather than generating a blanket baseline.

The minimal quality workflow uses read-only permissions, pinned action SHAs,
no provider secrets, a 15-minute deadline, frozen installs and `npm run quality`.
Required independent seeded CI failure/recovery proof remains an acceptance
gate until verified on the remote workflow. Jira owns development-key checks;
this workflow does not duplicate or prove Jira linkage. Update pins deliberately,
regenerate the relevant root lock, inspect audit/peer compatibility, and repeat
frozen installation plus affected behavior and failure/recovery checks. Do not
use peer bypasses or automatic audit fixes.

The workflow also runs `uv run --frozen python scripts/verify-quality-gates.py`.
This serial verification command places reversible synthetic probes in actual
checked paths, asserts each target and the aggregate fail for the intended
rule, removes the probe and asserts recovery. It restores original contract
bytes in `finally` and refuses to overwrite an existing source probe. Hold
exclusive checkout access while running it. Local execution does not establish
remote CI acceptance.

The [automated fixture runbook](../infra/local/README.md) covers isolated test-only Mongo/private S3, integrity, private access and owned cleanup. Run `npm run test:local` for fixture safety units; `npm run test:smoke` alone orchestrates the real credential-free synthetic runtime. These containers are never application defaults, developer provisioning or hosted fallback. The web/version/liveness diagnostics and opt-in real API readiness are accepted under SCRUM-16; P01.5 clean build/unit/smoke CI remains a separate gate. Quality success alone does not establish that outcome.

## Clean integration commands

From the repository root in PowerShell or a POSIX shell:

```sh
npm run bootstrap
npm run check
npm run test:unit
npm run build
npm run test:smoke
uv run --frozen --package shipsense-api python scripts/verify-integration-gates.py
```

`bootstrap` checks exact Node/npm/Python/uv versions, runs `npm ci`, checks lock
freshness and installs every Python workspace/group with `--frozen`. `check`
uses the existing quality/byte-contract gate. Units cover API contracts/lifespan,
local safety/evidence/queue boundaries, web validation/races and no-effect worker
smoke. `build` produces the Next.js production app and all three Python wheel/source
distributions; disposable distributions are built outside the repository.
`npm run verify` combines check, units, build and real smoke after bootstrap.

Only the isolated automated smoke gate requires a local Linux/amd64 Docker engine with Compose, the selected
Decision 0007 images (only those exact digests may download on first CI boot),
1.5 GiB available host memory, at least 2 GiB engine allocation and an installed
Chrome/Chromium. Detection supports Windows Chrome and Linux Google Chrome or
Chromium; `SHIPSENSE_CHROME` can identify an installed executable. No browser
download, library, user profile or cloud credentials are used. Missing/incompatible
tools fail the gate. Ports 3000, 8000, 37017 and 38333 must be free; stop an existing
developer runtime through its owner before running. No listener is killed automatically.

MongoDB's bootstrap wrapper copies only its two read-only mounted credential files
into a 1 MiB container tmpfs before the official entrypoint changes user. The tmpfs
directory is owned by `mongodb` with mode `0700`; its copied files use `0600`.
Host credential files remain owner-only inside the private state directory. This
supports Linux UID separation without making the host secrets broadly readable.
The S3 fixture similarly stages only its private identity file into seaweed-owned tmpfs0700/file0600. Its host lifecycle first validates the complete scoped identity, then supplies only the digest of those exact bytes; the wrapper requires matching bounded input and copied bytes before the upstream privilege drop. No credential values enter environment or arguments. Both wrappers fail closed when inputs or tmpfs are invalid. The integration gate checks actual backing, service UID/modes, host POSIX modes, and S3 missing/changed/oversized/unreadable input plus missing/malformed/mismatched digest refusals.

Each smoke uses the fixed `shipsense-ci-p01` namespace with fresh external private
state and credentials. The default `shipsense-local-p01` namespace and its volumes
are preserved. Runtime is serialized because both profiles retain the same fixed
data ports. Stale resources, owner/state mismatch, remote daemons and namespace
overrides are refused. The smoke explicitly selects `SHIPSENSE_DEPENDENCIES=test-fixtures`, independently of hosted application configuration. It seeds six fixtures twice, proves private access,
runs all eleven real adapter/readiness integration cases without skips, starts actual
Uvicorn and production Next, checks safe default503/configured200, stops/restores
each dependency and verifies readiness/liveness independence. An owned headless
browser asserts rendered success, API stop, retry/unavailable with cleared version,
and restart/retry recovery with focus retained. Screenshots support these assertions.

Set `SHIPSENSE_EVIDENCE_DIR` to a **new external directory** to retain sanitized JSON
and screenshots; otherwise an OS temporary directory is created. Never place it
under the product checkout. Process environments exclude inherited provider/agent
credentials and app settings. Private state and browser profiles are never uploaded.
The normal/failure/cancellation path stops owned processes and resets only validated
CI resources. Failure to verify ownership refuses deletion and retains private
state for diagnosis. An always-run CI step repeats the same ownership-checked cleanup:

```sh
uv run --frozen --package shipsense-api python scripts/verify-integration-gates.py --cleanup
uv run --frozen --package shipsense-api python scripts/integration-smoke.py --cleanup
```

Gate attempts retain ownership receipts and private state in fixed `gate-attempts`
children of that external evidence directory until verified teardown completes;
temporary-directory cleanup must not erase them while containers survive.
Use the original `SHIPSENSE_EVIDENCE_DIR` for recovery cleanup. The commands never
adopts another attempt or resets the developer profile. A forced process/host kill
can prevent in-process cleanup; CI's always-run step is the fallback. Do not prune
or delete unknown resources to get a green run.

`verify-integration-gates.py` temporarily appends byte drift to canonical OpenAPI,
requires the real contract gate to reject it, restores exact bytes in `finally`
and checks recovery. It then runs the real smoke with its upstream deliberately
stopped at the required success gate, requires failure plus zero remaining CI
resources, and reruns from fresh state to prove recovery. The standalone
`test:smoke -- --fail-upstream` is an intentional failing diagnostic, never a
skipped integration success. Hold exclusive checkout/runtime access for this proof.

The Integration workflow repeats these commands from a clean checkout with
read-only permissions, immutable action references, no provider secrets, a
30-minute job bound and three-day retention for only sanitized top-level JSON/PNG.
Quality success alone cannot replace this gate. Hosted configuration/transport/lifecycle tests run without provider calls; real managed MongoDB/Cloudflare R2 compatibility and permissions remain unverified without authorized endpoints/access. Isolated emulator success is never live hosted proof. Issuer/reference validation,
region/tier/residency/cost, production parity and P01 exit remain separate.
