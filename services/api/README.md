# Canonical API boundary

Owns canonical APIs, authorization, integrations and orchestration. Public local diagnostic exceptions expose no customer data: `GET /foundation`, `GET /api/v1/version`, `GET /health/live`, `GET /health/ready`, `/docs` and `/openapi.json`. Domain authorization arrives in P02; no permissive authorization middleware is installed. Do not expose this local profile as a secured deployment.

From the root: `uv sync --frozen --all-packages --all-groups`; `uv build --package shipsense-api`; `uv run --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log`. Inspect `/api/v1/version`, `/health/live`, `/health/ready`, `/docs` and `/openapi.json`. No credentials or backing service are required. `SHIPSENSE_PROFILE` defaults to `local`; any other profile fails startup without exposing its value. Stop with Ctrl+C. Disable raw Uvicorn access logging as shown: it otherwise includes untrusted URLs/query values. Application diagnostic logs contain only generated/validated request IDs and status codes.

Version is the fixed bounded release identifier `0.1.0-dev`; `observedAt` is fresh UTC per request. All responses use `Cache-Control: no-store` and `X-Request-ID`. Supply one optional `X-Request-ID` of 1–64 ASCII letters, digits, underscores or hyphens; invalid/duplicate values return safe 422 with a fresh generated reference. Unexpected exceptions return safe 500. Rejected values, exception text and dependency addresses never appear in the error envelope. OpenAPI contains the custom 422/500 models/examples, version success and readiness 503 examples.

Liveness reports only process availability. The application uses existing hosted MongoDB and private Cloudflare R2 endpoints. It does not start databases, storage services or containers. Copy the root `env.example` to ignored `.env`, fill its six connection placeholders privately, and load that file explicitly into the API process:

```sh
uv run --env-file .env --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

`SHIPSENSE_DEPENDENCIES` defaults to `hosted`. Mongo accepts authenticated `mongodb+srv://` or standard DNS-seed `mongodb://` URIs with mandatory TLS certificate/hostname verification; URL-encode credentials. Standard replica sets are supported without forcing a direct connection. Unsafe TLS/file/proxy/timeout URI options, duplicate options, local/IP targets and placeholders are refused. `SHIPSENSE_MONGODB_DATABASE` names the existing application database (not admin/config/local). No database, collection, index, bucket or record is created. The Mongo credential needs read access to the configured database's `fixtures` collection for the scoped infrastructure probe. This is not tenant authorization.

`SHIPSENSE_R2_ENDPOINT` is the HTTPS account S3 endpoint; `SHIPSENSE_R2_BUCKET` is an existing private bucket. Use bucket-scoped access ID/secret, not a Cloudflare management API token. Region is `auto`, signature is v4, TLS verification stays enabled and ambient AWS profiles/credentials/proxies are ignored. Bucket readiness uses only `HeadBucket`; there is no public URL, ACL change, bucket creation or seed. Keep buckets private in Cloudflare; a successful authorized probe does not prove anonymous denial or object permissions. See [Cloudflare's SDK setup](https://developers.cloudflare.com/r2/examples/aws/boto3/) and [Mongo connection targets](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/connect/connection-targets/).

Missing, placeholder, malformed or unsupported settings keep readiness503 and live/version/schema available. There is no local-state fallback. Logs expose only fixed unavailable/shutdown markers. Correct configuration requires restarting the API; subsequent readiness requests observe dependency failure/recovery. Hosted compatibility and live permissions remain unverified until authorized endpoints/access are supplied. Foundation profile remains `local`; production is refused until identity and durable queue/deployment gates are implemented. These placeholders do not authorize live provider calls or effects.

The web process needs only server-side `SHIPSENSE_API_ORIGIN`; do not load the API credential file into Next.js or use `NEXT_PUBLIC_` variables. Start the web separately using [its runbook](../../apps/web/README.md).

FastAPI lifespan owns one pooled async Mongo client, a four-thread private R2 client and a `MemoryQueue`. Authenticated Mongo scoped reads and R2 bucket probes must succeed; the queue probe describes this API process only. It proves no separate worker, cross-process communication, durable message delivery or Service Bus health. Nothing enqueues or consumes work during readiness. Shutdown disables readiness, closes the queue, drains bounded outstanding storage work and closes clients/executor. A later lifespan owns fresh resources.

`ReadinessGate` requires all three asynchronous probes, each with a one-second timeout within a three-second overall deadline and four concurrent request slots; excess requests fail closed. S3 admits at most four underlying calls, retaining slots after timeout/cancellation until work completes. Native socket/retry bounds cap underlying work. There is no success cache. Dependency errors return only the documented generic503, never names, addresses or credentials. Readiness is infrastructure access, not observed customer recovery, tenant authorization or production parity.

Run `npm run test:foundation` for diagnostic, hosted configuration/client transport, refusal and shutdown tests. `npm run test:smoke` is the credential-free automated fixture gate: it alone supplies `SHIPSENSE_DEPENDENCIES=test-fixtures` plus a validated private external `SHIPSENSE_LOCAL_STATE_DIR`, starts isolated synthetic containers and verifies actual test dependency outage/recovery and browser behavior. That selector is never a fallback or developer setup path; it cannot use hosted URLs. Details: [test-fixture safeguards](../../infra/local/README.md). Emulator success does not establish managed Mongo/R2 compatibility or live readiness. Generate canonical schemas with `npm run contracts:generate`; verify byte drift with `npm run contracts:check`. No public contract or migration is changed.
