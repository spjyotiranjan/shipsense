# Canonical API boundary

Owns canonical APIs, authorization, integrations and orchestration. Public local diagnostic exceptions expose no customer data: `GET /foundation`, `GET /api/v1/version`, `GET /health/live`, `GET /health/ready`, `/docs` and `/openapi.json`. Domain authorization arrives in P02; no permissive authorization middleware is installed. Do not expose this local profile as a secured deployment.

From the root: `uv sync --frozen --all-packages --all-groups`; `uv build --package shipsense-api`; `uv run --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log`. Inspect `/api/v1/version`, `/health/live`, `/health/ready`, `/docs` and `/openapi.json`. No credentials or backing service are required. `SHIPSENSE_PROFILE` defaults to `local`; any other profile fails startup without exposing its value. Stop with Ctrl+C. Disable raw Uvicorn access logging as shown: it otherwise includes untrusted URLs/query values. Application diagnostic logs contain only generated/validated request IDs and status codes.

Version is the fixed bounded release identifier `0.1.0-dev`; `observedAt` is fresh UTC per request. All responses use `Cache-Control: no-store` and `X-Request-ID`. Supply one optional `X-Request-ID` of 1–64 ASCII letters, digits, underscores or hyphens; invalid/duplicate values return safe 422 with a fresh generated reference. Unexpected exceptions return safe 500. Rejected values, exception text and dependency addresses never appear in the error envelope. OpenAPI contains the custom 422/500 models/examples, version success and readiness 503 examples.

Liveness reports only process availability. With no explicit local configuration, readiness returns 503 `DEPENDENCY_UNAVAILABLE`. To opt in, first follow the [owned local service runbook](../../infra/local/README.md), including explicit startup and seed. Set `SHIPSENSE_LOCAL_STATE_DIR` to that existing private external absolute state directory before launching the API. For example in PowerShell:

```powershell
$env:SHIPSENSE_LOCAL_STATE_DIR = "$env:LOCALAPPDATA/ShipSense/local-p01"
uv run --frozen --package shipsense-api uvicorn shipsense_api.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Use the same directory supplied to `local:up -- --state-dir` if customized. API startup only validates/reads configuration; it never creates state or credentials, starts containers, seeds records or contacts cloud services. Missing, malformed, linked, foreign-repository or unsupported configuration fails closed to readiness503 while version/live/schema remain available. Logs expose only a fixed unavailable marker. Correct configuration requires restarting the API; dependency recovery is detected on the next request without restart. Nonlocal profiles still refuse startup entirely.

FastAPI lifespan owns one pooled async Mongo client, a four-thread private S3 client and a `MemoryQueue`. Authenticated Mongo scoped reads and S3 bucket probes must succeed; the queue probe describes this API process only. It proves no separate worker, cross-process communication, durable message delivery or Service Bus health. Nothing enqueues or consumes work during readiness. Shutdown disables readiness, closes the queue, drains bounded outstanding storage work and closes clients/executor. A later lifespan owns fresh resources.

`ReadinessGate` requires all three asynchronous probes, each with a one-second timeout within a three-second overall deadline and four concurrent request slots; excess requests fail closed. S3 admits at most four underlying calls, retaining slots after timeout/cancellation until work completes. Native socket/retry bounds cap underlying work. There is no success cache. Dependency errors return only the documented generic503, never names, addresses or credentials. Readiness is infrastructure access, not observed customer recovery, tenant authorization or production parity.

Run `npm run test:foundation` for diagnostic, configuration refusal and cancellation/shutdown tests. With owned services running, set `SHIPSENSE_TEST_STATE` to the same directory and run `npm run test:readiness:integration`. These tests stop/restart only the owned Mongo and storage services and verify actual200→503→200, live/version independence, queue lifecycle, storage deadlines, capacity and cancellation. Do not run them concurrently with other lifecycle commands. Without explicit test configuration they skip; a skip is not real readiness proof. Generate canonical schemas with `npm run contracts:generate` and verify byte drift with `npm run contracts:check`; lifecycle wiring does not change the public contract. No migrations or customer persistence are introduced.
